# Инструкции для агента — examples

Прочитай README и инструкции изменяемого компонента, если они есть. Сохраняй чужую работу.
Текущая основная ветка — `master`; перед началом проверь её актуальную ревизию.

## Непрерывность одной задачи

Эти правила относятся к выполнению порученной работы; одно чтение или ревью её не запускает.
Местные проекты/поля/статусы трекера, проверки, ревью, разрешения merge и выкладки сохраняются.

- Одна логическая задача сохраняет исходный ключ во всех этапах, сессиях, агентах и репозиториях.
  Без явного поручения человека не создавай для продолжения новые задачи, Jira-подзадачи, дубли
  или GitHub issues. Существующие подзадачи и их история остаются. Без ключа используй согласованный
  запрос/план, не заводи карточку автоматически.
- Для простой задачи достаточно одного PR. Осмысленные этапы могут иметь несколько PR в одном
  или разных репозиториях; каждый связывается с той же задачей, называет свой объём и зависимости,
  собственные проверки с доказательствами и оставшуюся общую работу за пределами этого PR.
  Сохраняй историю всех PR, включая закрытые без merge и заменённые; их работу не засчитывай
  в подтверждённый результат без доказательства включения в принятую ревизию.
- До реализации проясни нерешённые продуктовые вопросы: цель, сценарии, дефолты, форматы,
  ограничения и проверяемые критерии. Сохрани использованный раунд продуктового уточнения:
  вопросы, подтверждённые ответы, принятые решения и их источники. При смене агента этот раунд
  продолжается из записи; уже согласованное не спрашивай заново. Технические вопросы решай
  внутренне по коду и проверкам. Новое существенное противоречие продукта — явный блокер:
  запиши конфликт и нужное решение, приостанови зависимую часть до ответа владельца.
  Память чата не заменяет доступную следующему агенту запись.
- В той же задаче или уже связанном общем плане веди `Task-Checkpoint: <ключ/ID плана>`:
  цель/границы; стабильные ID критериев → статус/доказательство; решения/вопросы; весь реестр PR
  (репозиторий, URL, этап, критерии, ветка, точные base/head/merge SHA, CI/review SHA и ссылки,
  зависимости; состояние доставки, точная доставленная ревизия/артефакт, окружение и доказательство
  доступности — отдельно от merge SHA); владелец этапа, состояние исполнителя (активен, завершил
  этап или ждёт передачи), следующий владелец/шаг, блокеры и оставшийся объём.
- На входе, при возобновлении и непосредственно перед записью перечитай задачу, комментарии,
  checkpoint и все связанные PR. Сохраняй чужие результаты и ручные решения; правь только свою
  запись либо добавь связанный следующий снимок. При неясном владении согласуй передачу,
  не запускай конкурирующего исполнителя. Для одного события используй стабильный ключ:
  тип события + ключ задачи + репозиторий/PR + точная ревизия (для решения — его стабильный ID).
  Перед повтором, в том числе после таймаута, найди фактическую запись по этому ключу,
  перечитай её и выполни только недостающее; не создавай повторный комментарий или переход.
- После этапа, решения, успешной или неуспешной проверки, перед передачей и перед окончанием
  сессии обнови checkpoint и прочитай его обратно.
  При недоступности основного источника предпочти уже опубликованную задачу, общий план, PR
  или commit, доступные преемнику; пометь снимок как несинхронизированный с основным источником.
  Точно укажи последний опубликованный SHA и что осталось неопубликованным, незакоммиченным
  или несохранённым, включая затронутые пути и способ получить изменения. Если возможен только
  локальный аварийный черновик, явно запиши блокер сохранения/передачи контекста: локальный файл не может быть
  единственным долговечным источником контекста. Передача и сохранение контекста не завершены,
  пока снимок и изменения не опубликованы доступным преемнику способом по местным разрешениям.
  Не объявляй общую запись/статус обновлёнными и не закрывай задачу; после восстановления сначала
  перечитай актуальные данные и объедини изменения, сохранив историю.
- Перед сдачей сверь свежие base/head SHA и зависимые изменения. Изменились база, head или
  зависимость — повтори затронутые проверки/ревью на новой комбинации; старый зелёный статус
  не доказывает её корректность. Общий «Результат» и завершение относятся ко всем критериям,
  обязательным PR и необходимой по местным правилам доставке/QA; успех одного этапа не закрывает
  остаток. Частичную готовность, непроверенное и следующий шаг укажи явно.
